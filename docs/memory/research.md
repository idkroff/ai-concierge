# 2. Подходы к памяти LLM-агентов

## 2.1. Сравнение фреймворков

| | Mem0 | LangMem | Letta (MemGPT) | Zep / Graphiti |
|---|---|---|---|---|
| Механизм записи | Статья: извлечение фактов из пары сообщений + сводки + последних m=10 сообщений, затем для каждого факта LLM выбирает ADD / UPDATE / DELETE / NOOP по top-s=10 похожим записям [[1]](#src). С v2.0.0 (16.04.2026) — один LLM-вызов, только ADD [[3]](#src) | Фоновый `memory manager` извлекает записи по Pydantic-схемам; Profile (один документ, обновляется на месте) или Collection (набор записей с reconciliation) [[5]](#src) | Агент сам редактирует in-context «memory blocks» инструментами `memory_replace / memory_insert / memory_rethink`; архив — векторная БД через инструменты [[8]](#src) | Факты — рёбра временного графа знаний; LLM извлекает `valid_at / invalid_at` из текста [[10]](#src) |
| Дедупликация | Статья: решение LLM по top-10 похожим; v2: MD5-хэш точных дублей + ранжирование при чтении [[3]](#src) | LLM-менеджер решает insert / update / delete; порогов нет [[5]](#src) | Нет явной; агент переписывает блок | Сравнение только между рёбрами одной пары сущностей [[10]](#src) |
| Версии и противоречия | Статья: UPDATE/DELETE; v2: «new fact is stored alongside the old one» [[3]](#src) | Collection требует «deleting/invalidating or updating/consolidating» [[5]](#src) | Блок — строка, перезаписывается на месте; прежняя версия только в истории чата **[не проверено]** | Би-темпоральная модель: старое ребро инвалидируется (`t_invalid := t_valid` нового), не удаляется; приоритет новой информации [[10]](#src) |
| Фон vs hot path | Фон (add после ответа) | Оба; фон — «higher recall» без латентности; `ReflectionExecutor(after_seconds)` отменяет задачу при новом сообщении [[6]](#src), [[7]](#src) | Hot path + фоновые «sleep-time» агенты, «does not ask you for approval» [[9]](#src) | Фон (ингест эпизодов) |
| Что берём | Таксономию операций (дубль / замена / новый) и передачу активных фактов категории в промпт для согласованной формулировки; само решение — детерминированно в Go (D-1) | Разделение Profile/Collection; дебаунс; явный компромисс precision/recall | Маленький «core»-профиль целиком в промпте | Инвалидацию вместо перезаписи; два времени (валидность / запись) |

**Mem0** (arXiv 2504.19413, апрель 2025; ECAI 2025). Два этапа: extraction и update; в update для каждого факта «retrieves the top s semantically similar memories», и «the LLM itself determines which of four distinct operations to execute» [[1]](#src), [[2]](#src). Важное изменение: Mem0 OSS v2.0.0 заменил двухшаговую схему на «Single LLM call: extract all distinct new facts → … Hash-based deduplication (MD5) → batch insert», операции UPDATE/DELETE убраны, память только накапливается; `custom_update_memory_prompt` → `custom_instructions`, `top_k` 100→20 [[3]](#src), [[4]](#src). Это ровно наш бюджет NFR-07 (один вызов), но ценой отказа от консолидации — у нас её закрывают версии (FR-15).

**LangMem** (LangChain, февраль 2025). Типы памяти: semantic (факты/предпочтения), episodic (опыт), procedural (правила). Фоновая формация «occurs after a conversation … without slowing down the immediate interaction»; «If the system over-extracts … reduced precision … If it under-extracts … low recall» [[5]](#src). Дебаунс: `ReflectionExecutor` «Cancels old tasks when new messages arrive», в проде задержка 30–60 мин [[7]](#src).

**Letta / MemGPT.** Блоки памяти всегда в контексте (рекомендация < 50 000 символов, < 20 блоков), файлы — read-only, архив — вектора, ~300 токенов на запись [[8]](#src). «Sleep-time»/«Dreaming» — фоновые субагенты консолидируют память «without interrupting your active work» [[9]](#src).

**Zep / Graphiti** (arXiv 2501.13956, январь 2025). Четыре времени на ребре: `t_valid / t_invalid` (мир) и `t'_created / t'_expired` (система). Противоречие → инвалидация старого ребра, факт переформулируется («Maria used to work as a junior manager, until…»); если пользователь поправил дату, `valid_at` обновляется [[10]](#src), [[11]](#src). DMR 94.8% против 93.4% у MemGPT; LongMemEval до +18.5% точности и −90% латентности к full-context [[10]](#src).

## 2.2. Бенчмарки

Числа из статьи Mem0 на LoCoMo (судья GPT-4o-mini; J — доля верных ответов, p95 — латентность ответа, токены — размер контекста ответа) [[2]](#src):

| Система | J, % | p95, с | Токенов |
|---|---|---|---|
| Full-context (весь диалог в промпте) | **72.90** | 17.1 | 26 031 |
| Mem0g (граф) | 68.44 | 2.59 | 3 616 |
| Mem0 | 66.88 | 1.44 | 1 764 |
| Zep | 65.99 | 2.93 | 3 911 |
| LangMem | 58.10 | 60.4 | 127 |
| OpenAI memory | 52.90 | 0.89 | 4 437 |
| A-Mem | 48.38 | 4.37 | 2 520 |

Выводы: full-context точнее всех, но в ~12 раз медленнее (17,1 с против 1,44 с) и в ~15 раз дороже по токенам, чем Mem0; извлечённая память — компромисс в пользу цены и латентности. Другие бенчмарки: LongMemEval (ICLR 2025) — 500 вопросов, пять способностей (information extraction, multi-session reasoning, temporal reasoning, knowledge updates, abstention), у коммерческих ассистентов «30% accuracy drop» [[12]](#src); A-MEM (NeurIPS 2025) — Zettelkasten-заметки со связями и «memory evolution» [[13]](#src).

**Оговорка о метриках.** Аудит Penfield Labs (апрель 2026, не рецензирован, артефакты открыты): 6.4% эталонных ответов LoCoMo ошибочны (99 из 1 540), LLM-судья принимает 62.81% намеренно неверных ответов; теоретический максимум ≈ 93.6% [[14]](#src), [[15]](#src). Маркетинговые цифры 2026 (Mem0 92.5% LoCoMo и 94.4% LongMemEval, Zep 94.7%) получены другими моделями-ответчиками и судьями и несопоставимы с таблицей выше [[16]](#src). Для нас это значит: качество экстракции мерим своим размеченным набором (NFR-06), а не чужими бенчмарками.

# 3. Риск записи без спроса

| Источник | Суть | Числа |
|---|---|---|
| MINJA (arXiv 2503.03704, NeurIPS 2025) [[17]](#src) | Инъекция в память агента только через обычные запросы, без доступа к хранилищу | Injection success 98.2%, attack success 76.8%; защита на уровне промпта (GPT-4o как судья) не обобщается между агентами — «prompts that are precise lack generality, while general prompts may incur high false positives»; санитизация на уровне эмбеддингов «fails in practice» |
| SpAIware (J. Rehberger, сентябрь 2024) [[18]](#src) | Indirect prompt injection записала в долгосрочную память ChatGPT инструкцию эксфильтрировать каждый ход | Вектор эксфильтрации закрыт в ChatGPT 1.2024.247; манипуляция памятью осталась открытой проблемой |
| OWASP Top 10 for Agentic Applications 2026, ASI06 «Memory and Context Poisoning» (09.12.2025) [[19]](#src) | Отравление персистентной памяти живёт дольше сессии и срабатывает позже | Меры: валидация записей, scope по пользователю, «auditable chain-of-custody for every memory write», версионирование с откатом, просмотр и очистка |
| arXiv 2606.04329 [[20]](#src) | Агрессивные политики записи повышают качество и расширяют поверхность атаки | — |

Следствия для дизайна (FR-14 сохраняет факт без вопроса, поэтому компенсирующие меры обязательны):

1. Источник записи — только текст самого пользователя. Транскрипты звонков в ресторан, ответы ресторана и любые внешние тексты в экстрактор не попадают (ASI06, MINJA).
2. У каждой версии факта — `source_ref` на сообщение и `created_at` (FR-20); «исправлено вручную» — отдельный источник.
3. Версии вместо перезаписи: новое значение делает старое неактивным, но не удаляет (FR-15); «Забыть» возвращает предыдущую версию (FR-14).
4. Soft delete с немедленной фильтрацией и физическая очистка ≤ 24 ч (NFR-04) — чтобы откат и аудит были возможны.
5. Пользователь видит и правит всё, что сохранено: `/memory`, «Исправить», «Удалить», `/forget` (FR-17–FR-19); факт показывается на экране подтверждения строкой «Учту:» (FR-16).
6. Консервативный экстрактор: precision ≥ 90% важнее recall ≥ 70% (NFR-06); сведения о здоровье и о других людях — отдельный запрет в промпте и в тест-наборе.

## 4.7. Рекомендация и стоимость

Фоновая экстракция (FR-13) и разбор фраз в hot path (FR-06–FR-09): **Alice AI LLM Flash** через OpenAI-совместимый API с `json_schema`. Резерв на случай провала тест-набора — YandexGPT Pro 5.1 (есть в обоих API). Расчёт на один вызов экстракции при ~1 500 входных и ~150 выходных токенов:

| Модель | Вход | Выход | За вызов | 30 000 вызовов/мес (1 000 сообщений/день) |
|---|---|---|---|---|
| Alice AI LLM Flash | 1 500 × 0,1 / 1 000 = 0,15 ₽ | 150 × 0,2 / 1 000 = 0,03 ₽ | **0,18 ₽** | **5 400 ₽** |
| — то же, системный промпт ~1 000 токенов из кэша | 1 000 × 0,025 / 1 000 + 500 × 0,1 / 1 000 = 0,075 ₽ | 0,03 ₽ | 0,105 ₽ | 3 150 ₽ (кэш не гарантирован) |
| YandexGPT Pro 5.1 | 1,20 ₽ | 0,12 ₽ | 1,32 ₽ | 39 600 ₽ |
| Alice AI LLM | 0,75 ₽ | 0,18 ₽ | 0,93 ₽ | 27 900 ₽ |

Эмбеддинг извлечённого факта (~20 токенов) — 0,0002 ₽, пренебрежимо. Один вызов экстракции на сообщение закрывает NFR-07; средняя нагрузка 1 000 сообщений/день ≈ 0,012 RPS — квота 10 RPS на векторизацию не ограничивает.

# 5. YDB

## 5.1. Векторный поиск

Точный поиск — UDF-модуль `Knn`: `Knn::CosineSimilarity(String, String) -> Float?`, `CosineDistance` (= 1 − cos), `InnerProductSimilarity`, `ManhattanDistance`, `EuclideanDistance`. Векторы сериализуются `Knn::ToBinaryStringFloat` (а также `Uint8 / Int8 / Bit`), перед записью `Untag`, хранятся в колонке `String`; запрос — `ORDER BY Knn::CosineDistance(embedding, $q) LIMIT $k`, без индекса, «full support for transactions, including in strict consistency mode» [[34]](#src). У нас кандидаты для дедупликации выбираются `WHERE user_id = … AND category = …` — это ≤ 50 фактов на пользователя (NFR-08), попарное сравнение 256-мерных векторов укладывается в единицы миллисекунд; векторный индекс не нужен.

Когда индекс понадобится: поиск по всем пользователям сразу или тысячи фактов у одного пользователя. Тогда — `vector_kmeans_tree`: `ALTER TABLE t ADD INDEX i GLOBAL USING vector_kmeans_tree ON (user_id, embedding) WITH (distance=cosine, vector_type="float", vector_dimension=256, clusters=…, levels=…, overlap_clusters=3)`; `vector_dimension` 1…16 384, `clusters` 2…2 048 (реком. 64–512), `levels` 1…16 (реком. 1–3); запрос обязан указывать `VIEW i`, `PRAGMA ydb.KMeansTreeSearchTopSize` по умолчанию 1 [[35]](#src), [[36]](#src), [[37]](#src). Ограничения: индекс не обновляется во время построения; на пустой таблице вырождается в full scan; после массовых обновлений качество падает [[35]](#src). Статус: введён в 25.1 (RC 25.1.2.7, 14.07.2025, выключен флагом), включён по умолчанию в 25.2 (RC 25.2.1.10, 21.09.2025), ускорен в 25.4 (05.06.2026) [[38]](#src); в Yandex Cloud FAQ описана тарификация RU для `vector_kmeans_tree` [[39]](#src).

## 5.2. JSON и JsonDocument [[40]](#src), [[41]](#src), [[42]](#src)

| Свойство | JsonDocument |
|---|---|
| Представление | бинарное индексированное; JsonPath без полного парсинга |
| Нельзя | сравнивать; **использовать в PK и в ключе вторичного индекса** |
| Не сохраняет | порядок ключей, форматирование, дубликаты ключей |
| Накладные расходы | +20–30% к объёму |
| Функции | `JSON_VALUE`, `JSON_QUERY`, `JSON_EXISTS`, `CAST(s AS Json)` |
| JSON-индекс | `INDEX i GLOBAL SYNC USING json ON (payload)` ускоряет `JSON_EXISTS / JSON_VALUE`; только SYNC, без COVER, только row-таблицы |

Вывод: категория, значение, нормализованное значение, версия, `source_ref` — обычные колонки; JsonDocument в схеме памяти не используется (сырой ответ экстрактора не хранится; при необходимости — в логах, не в YDB).

## 5.3. TTL [[43]](#src)

Одна TTL-колонка на таблицу; типы Date / Datetime / Timestamp / Uint32 / Uint64 / DyNumber; `eviction_time = value + evict_after`; фоновая операция на партицию с интервалом (по умолчанию 1 ч, минимум 15 мин); «TTL doesn't guarantee that the item will be deleted exactly at eviction_time, it might happen later». Синтаксис: `WITH (TTL = Interval("PT0S") ON purge_at)`, `ALTER TABLE … SET (TTL = …)`. Для NFR-04 (физическое удаление ≤ 24 ч): при «Удалить всё» ставим `deleted_at` (чтение фильтрует сразу) и `purge_at = now()`; TTL `PT0S` удаляет строки фоном, а PurgeJob (при старте и каждые 6 ч) делает явный DELETE по `user_id` во всех таблицах и проверяет COUNT = 0, потому что TTL жёсткой гарантии не даёт (D-9).

## 5.7. Часовой пояс (FR-05, FR-06, FR-08)

Типы `Date / Datetime / Timestamp` в YDB — «UTC time», без часового пояса; `TzTimestamp` «not supported in table columns» [[40]](#src). SRS фиксирует A-2: часовой пояс пользователя — Europe/Moscow. Следствие: все `Timestamp` в таблицах — UTC; «сегодня», «завтра», «день недели» и проверка «бронь уже прошла» (FR-08) вычисляются в Go через `time.LoadLocation("Europe/Moscow")` до записи и после чтения; для показа и поиска по дате хранится дополнительно локальная дата брони (`booking_date_local`, `Date`). Ошибка на границе суток (23:30 MSK = 20:30 UTC) без этого даёт неверное «сегодня/завтра».

## 5.8. Деградация при недоступности LLM или YDB (NFR-02)

NFR-02: команды, которым нужна память, «за ≤ 10 с получают ответ „Память временно недоступна, попробуйте позже“, и бот не звонит». Бюджет: таймаут контекста на вызов LLM 5 с (sync-режим допускает до 15 мин [[25]](#src), поэтому таймаут задаёт клиент), запросы к YDB через `db.Query().Do` с таймаутом 2 с и одним повтором (`query.WithIdempotent()` для чтений) [[46]](#src); суммарно ≤ 10 с. Фоновая экстракция при ошибке не повторяется бесконечно: один повтор, затем сообщение теряется с записью в метрику (FR-13 допускает recall ≥ 70%). Новая бронь без памяти — путь текущего бота.

# 9. Что не удалось проверить

1. **YDB**: статус векторного индекса (GA/experimental) явно не помечен в docs; дата появления в Yandex Cloud serverless и версия YDB под serverless не опубликованы. Поддержка клиентских KMS-ключей для serverless YDB не найдена (вероятно, нет).
2. **Шифрование serverless YDB и NFR-09**: для serverless-базы нет ни отдельного заявления о шифровании at rest, ни настройки в консоли/Terraform — только общая норма стандарта «all user data at rest is encrypted at the Yandex Cloud level» [[52]](#src). Критерий приёмки NFR-09 («конфигурация Terraform и IAM задаёт регион и шифрование») буквально не выполним. Предложение: фиксировать регион в Terraform (`location_id = "ru-central1"`), шифрование — ссылкой на стандарт с пометкой «включено по умолчанию, настройки нет», и переформулировать NFR-09: «Данные памяти лежат в YDB в регионе ru-central1; шифрование at rest обеспечивается платформой по умолчанию (ссылка на стандарт безопасности Yandex Cloud)».
3. **Yandex AI Studio**: список моделей с поддержкой `jsonSchema` и function calling не опубликован (в том числе для Alice AI LLM Flash через OpenAI-совместимый API); отдельного RPS для sync-генерации нет (только квота «2 одновременных»); что означает «без подписки» — не раскрыто; максимальная длина входа для эмбеддингов v2 не указана.
4. **Mem0**: детали `linked_memory_ids` и порогов нового алгоритма — из GitHub-обсуждений, не из docs.
5. **LoCoMo**: размер диалогов различается по источникам (статья Mem0: ~600 реплик / 26 тыс. токенов; другие пересказы — 16 тыс.) — взято из статьи Mem0.
6. **Telegram**: 100 кнопок / 8 в ряду — константы python-telegram-bot, не официальная спецификация; тайм-аут ответа на callback (~10 с) — только из вторичных источников; официального ограничения по времени на редактирование *собственных* сообщений бота не найдено.
7. **ChatGPT**: страницы help.openai.com и openai.com отдают 403 при прямом запросе — цитаты взяты из поисковых сниппетов официальных статей; индикатор «Memory updated» напрямую не подтверждён.
8. **Google / Gemini**: что именно «Call for Me» и «Ask for Me» запоминают о пользователе между звонками — не документировано; тег «Your saved info» в ответах Gemini — из release notes через вторичные источники (страница release notes редиректит); расширение бронирования ресторанов в AI Mode за пределы США и Канады (UK, Австралия, Индия) — только по пересказам.
9. **Инциденты 10.2026**: состав затронутых сервисов по статус-панели напрямую не прочитан (страница рендерится скриптом), поэтому в §5.5 используются только даты и факт остановки ДЦ по данным СМИ; влияние на Managed Service for YDB в документе не утверждается. Официальная страница загрузки MyStem (yandex.ru/dev/mystem) на 17.10.2026 отдаёт 404 — сведения о версии и платформах из §5.6 убраны, оставлено только лицензионное соглашение.
10. **Letta**: утверждение «блок перезаписывается на месте, предыдущая версия только в истории чата» — из стороннего разбора, не из docs.
